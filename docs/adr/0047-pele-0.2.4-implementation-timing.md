# ADR-0047: Pele 전환 0.2.4 구현 시점과 전환·복구 계약

## 배경
- ADR-0045는 Pele 1.7.0 `pele/lazy` 전환을 채택하고 구현 시점을 2026-10-22 이후 0.3.0으로 정했다(#179).
- 사용자가 2026-10-20 “pele은 0.2로 끌고 오기”를 확정했다. #179는 0.2.4로 이동하고 `tuck`→`focus`로 바뀌었다.
- 바뀐 것은 시점뿐이며 ADR-0045의 렌더러·보안·호환성·접근성·성능 조건은 유효하다.
- ADR-0034의 `Superseded by ADR-0045` 링크는 역사 기록으로 보존한다. 본 ADR은 ADR-0045의 렌더 계약과 ADR-0034의 마크다운·폴백 계약을 승계한다.

## 결정
- Pele 1.7.0 `pele/lazy`(`renderAsync`+사용 도식 등록) 전환을 0.2.4에서 구현한다. 실사용 전 완료를 목표로 하되 검증 미통과 시 배포 전환만 보류하고 0.2.4 범위·#179는 유지한다. 병합 전 현재 배포는 Mermaid를 유지한다.
- ADR-0045의 수용 조건을 유지하며 일정 단축으로 완화하지 않는다.
  - `MermaidDiagram` 인터페이스·원문 `pre/code` 폴백·접근성 계약 유지
  - 71개 도식 전수, 무효/미지원·타임아웃·언마운트 경합 처리
  - script/`on*`/`foreignObject`/외부 URL/위험 속성 0건, CSP 위반 0건, 악성 샘플 회귀
  - `--moi-*`↔Pele CSS 변수, 라이트/다크·대비
  - 320/375/768/1024/1280 캡처, 긴 한국어·AWS 서비스명·가로 오버플로 0
  - 첫 SVG 누적 로드·cold/warm 수치, 롤백 경로
  - `THIRD_PARTY_NOTICES`·lockfile·번들·BDD/단위 테스트 갱신
  - 호환성 확인 후 Mermaid 제거, 이중 번들 장기 유지 금지
- 기준 배포(현재 UI)와 Pele 배포의 SHA·버전·시각을 분리 기록한다. `e1259d6d`는 ADR-0045 당시 기록이며 최신 SHA는 전환 시 #179에 남긴다.
- 롤백은 코드/정적 자산 버전 복구와 D1 복구를 구분한다. 이번 전환은 DB 변경이 없을 것으로 예상하며, 변경이 필요하면 별도 승인·백업·복구 절차 없이는 배포하지 않는다.
- 워커는 자체 판단으로 remote write·deploy하지 않는다. o/사용자 승인 후 수행한다.

## 결과
- 긍정: 성능 효과(첫 SVG JS 약 94% 감소, cold p50 13.4→0.6ms)와 `foreignObject` 제거를 0.2.4에서 얻는다.
- 부정/제약: 일정 압축으로 검증·리뷰 병목 위험이 커진다. HTML 라벨 평문 처리·`%%{init}%%` 무시 등 호환 제약이 남고, 검증 미통과 시 실사용 배포는 Mermaid를 유지한다.
- 일정 변경은 범위·수용 조건 변경이나 완료 증거 승인이 아니다.

## 전환·복구 계획
1. 전환 전 최신 `dev`·배포 SHA·버전·Mermaid 동작을 #179에 기록한다.
2. 전환 PR에서 수용 조건 전체를 증거와 함께 검증하고 실패 항목은 병합 blocker로 둔다.
3. 통과 후에만 Pele 배포하고 SHA·버전·시각을 기준 배포와 분리 기록한다.
4. 코드 롤백은 직전 배포 SHA의 정적 자산·Worker 버전으로 되돌린다. D1 복구는 예상하지 않으며 DB 변경 시 별도 승인·백업 절차를 따른다.
5. 롤백 후 Mermaid 기준 배포의 해설·도식·테마 정상 여부를 확인한다.
6. 실계정 확인은 기술 검증·배포와 별도로 수행하고 결과를 #179에 남긴다.

## 대안과 금지 사항
- 0.3.0 시점 유지 — 사용자 확정과 충돌해 기각.
- 실사용 직전 무검증 전환 — 71개 전수·보안·접근성·viewport 증거 없이는 병합·배포 금지.
- 일정 단축으로 검증·viewport·도식 수를 줄이는 것 — 금지.
- Mermaid/Pele 이중 렌더러 장기 유지 — 금지. 호환성 확인 후 Mermaid 제거.
- 워커의 자체 remote write·deploy — 금지.
