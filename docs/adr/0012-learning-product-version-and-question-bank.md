# ADR-0012: 0.2.0 학습 제품 범위와 버전·문제은행 운영 정책

## 배경
- 0.1.0~0.1.4는 로그인·세션·배포 토대다. 이후 AWS SAA 학습의 핵심인 20문제 풀이·오답 반복 기능을 0.2.0 목표로 추가한다.
- 기존 ADR-0008의 '다음 큰 기능은 1.0.0' 및 수동 Milestone 연결 방침은 최신 사용자 합의·AGENTS.md의 모든 Issue Milestone 필수 방침과 충돌한다.
- 상세 구현 순서, 하위 Issue 및 0.2.x Milestone은 Mac mini AI 에이전트가 추후 분할한다. 본 ADR은 제품 계약/아키텍처 방향을 확정하며 분할 자체를 선행 구현으로 간주하지 않는다.

## 결정 1 — 버전 및 작업 거버넌스
- 0.1.0~0.1.4의 인증 단계는 유지한다. 다음 학습 기능 목표 버전은 **0.2.0**이며, 기존의 '다음 1.0.0' 규칙을 대체한다.
- 0.2.0은 **최종 출시 완료 목표**다. 하위 기능·의존성에 따라 에이전트가 0.2.x 등의 구현 단계와 Issue/Milestone을 제안·분할한다. 단 확정된 제품 요구사항을 임의 축소/변경할 수 없다.
- 모든 GitHub Issue는 적절한 Milestone에 연결한다. 생성은 사용자 수동 또는 별도 명시 요청, 연결은 에이전트가 수행한다. 적절한 Milestone이 없으면 임의로 잘못된 Milestone에 붙이거나 무단 생성하지 말고 생성 요청을 제기한다.
- 500문제 전체 검수와 기능 BDD/CI/배포 검증을 통과하기 전에는 **0.2.0 출시 금지**.

## 결정 2 — 시험·문제은행
- 우선 지원 시험: **AWS Solutions Architect – Associate(SAA-C03)**, 한국어 문제·한국어의 간결한 해설; AWS 서비스명과 공식 기술 용어는 영문 유지.
- 최초 공개 문제 **정확히 500개**, AI 신규 제작. SAA-C03 공개 시험 영역 배분 목표: 보안 30%(150), 복원력 26%(130), 성능 24%(120), 비용 최적화 20%(100). 공식 문서의 공개 가이드를 참조하며 실제 시험 문제/덤프를 무단 복제하지 않는다.
- 단일 선택 및 복수 선택 지원. 선택지 고유 ID 집합을 기준으로 **완전 정답** 채점. 각 문제에 시험, 영역, 본문, 보기, 정답 수/정답 ID, 짧은 핵심 해설(권장 1~2문장), AWS 공식 문서 근거 URL, 품질 검수·게시 상태, 개정 이력 포함.
- 문제 ID·문제 개정 버전·보기 ID·화면상 번호/위치를 분리. 화면 번호·문제 순서·보기 위치에 정답 패턴이 생기지 않게 섞고, 세트 내 중복 금지.
- 정답 선택지만 유독 길거나 자세하고 오답이 짧은 식의 단서 금지. 선택지 길이·문장 구성·정보량, 실질적 중복, 정답 위치 편향, AWS 근거와 정답 일치 여부를 자동 검수. 단순 URL 유효성만으로 정답 타당성을 보장한다고 간주하지 않는다.
- 문제 원본은 **D1**, Hono/Workers 관리 API는 관리 토큰 인증의 JSON 일괄 등록+단건 CRUD, 수정/비활성화·버전/감사 로그, 검수 실패 보고 및 멱등 등록 지원. 사용자 풀이 이력이 있는 문제는 물리 삭제 대신 비활성화. 다른 자격시험의 데이터·영역·출제 정책도 저장 가능한 시험 독립 구조를 사용한다.
- 최초 500문제 생성·검수는 **Mac mini AI 에이전트**에서 실행하고 인증된 관리 API로 D1에 등록. 등록 문제는 자동 검수 통과 즉시 게시 가능 상태가 되며 별도 수동 승인 단계는 요구하지 않는다. 다만 서비스 0.2.0 배포는 500문제 모두 검수 통과 후.
- 문제 관리 API는 카카오/PASETO 사용자 세션과 분리된 **작업 주체별 관리 토큰**만 허용. 토큰 개별 폐기·교체, 서버측 해시 검증, Secret/안전한 자격증명 저장, 요청 감사 로그 및 로그 redaction, 브라우저에 관리자 토큰 노출 금지.

## 결정 3 — 일반 20문제 풀이
- 계정·시험별 활성 20문제 세트는 **최대 하나**. 전체 범위(기본), 특정 시험 영역, 취약 영역 추천을 통한 영역별 풀기 지원. 다른 시험은 별개.
- 전체 범위의 20문제는 공식 출제 영역 비중을 고려한 **가중 무작위**이며 매 세트 영역별 개수 고정은 아니다. 영역별 풀이는 선택 영역 안에서만 추출.
- 아직 풀지 않은 문제를 우선 채우고, 미풀이를 소진하면 전체 문제에서 과거 **유효 누적 오답 횟수에 가중치**를 준 확률적 추출. 과거 틀렸더라도 최근 맞힌 문제와 항상 맞힌 문제도 선택 가능. 동일 세트 중복 불가.
- 시작 시 **문제 개정 버전과 보기 순서를 스냅샷으로 고정**; 새로고침·기기 변경·이어 풀기 후에도 유지. 같은 문제를 다른 회차에 다시 만났을 때는 보기 순서 새로 섞기.
- 일반 세트는 **20문제 최종 제출 시 일괄 채점**, 제출 전 정답 비공개. 시간제한·타이머·자동 제출 없음.
- 답안 선택 / 의도적 Pass / 미응답을 구분. 최종 제출은 미응답이 있어도 경고 및 확인 후 허용; Pass와 미응답은 오답 및 오답 복습 대상. 제출 전 Pass 취소·답변 가능.
- 제출 후 전체 20문제에 대해 선택한 답·정답·짧은 해설·AWS 근거 링크·북마크를 제공하고 정답/오답/Pass/미응답 및 정답률 요약.
- 세트 포기는 명시적 확인 후 `abandoned`로 기록하고, 채점/진도/통계에는 반영하지 않는다. 포기 당시 북마크는 유지. 채점 완료/포기 후 새 세트 시작 가능. 완료한 모든 과거 세트를 날짜·영역·정답률 목록(페이지네이션)과 상세 결과로 재조회한다.

## 결정 4 — 오답·북마크 복습
- 오답/Pass/미응답 제출 이력은 **계정별 영구 보존**하며, '현재 복습 필요' 표시는 삭제와 별도. 다시 정답이어도 이력 유지. 북마크는 개인별 독립 상태로, 풀이 중 및 채점 결과/해설에서 추가·해제 가능.
- 오답 복습은 누적 **유효** 오답 횟수 가중 무작위, 북마크 복습은 **균등 무작위**. 두 모드 모두 한 문제씩 즉시 채점, 문제 수·시간 제한 없음, 사용자가 직접 종료.
- 각 복습 모드는 독립된 진행 회차를 저장하여 방문 후 이어 풀기. 회차 시작 시 대상과 순서를 고정하고 회차 내 같은 문제 중복 없음. 대상을 모두 소진하면 최신 대상 목록을 다시 섞어 다음 회차 시작. 회차 진행 중 늘거나 줄어든 대상의 변경은 **다음 회차부터** 반영.
- 제출·채점된 개별 복습 시도는 즉시 계정 이력으로 보존; 미채점 문제는 종료 시 오답 처리하지 않는다.
- 오탈자/의미 동일 표현 수정은 기존 누적 오답 가중치를 유지. 정답·문제 조건·실질적 보기 변경은 새 문제 개정 버전의 가중치를 초기화하고 새 버전을 미풀이로 취급하되 원본 이력과 북마크는 보존.

## 결정 5 — 저장·복구·인증
- **D1이 확정된 진도/답안의 진실 원천**. 서버에 세트·회차·문제/보기 스냅샷·답안·채점·북마크를 사용자 UUID/시험 ID 기준으로 저장.
- localStorage는 계정별 구획된 미전송 답안 복구용 임시 데이터, sessionStorage는 탭별 UI 위치. **PASETO/세션/관리 API 토큰은 어느 브라우저 저장소에도 저장하지 않는다**(ADR-0005/0006 유지).
- 자동 저장 상태(저장 중/서버 저장됨/오프라인 임시 보관/충돌)는 실제 상태대로 표시. 네트워크 재연결 후 재전송하며 **서버 성공 전 저장 완료로 표시 금지**.
- 카카오 재로그인 시 **계정당 단일 활성 PASETO 세션**. 새 로그인 성공 시 기존 세션의 jti를 서버에서 폐기하고 이전 기기 API 요청 거부 및 만료 안내. 이전 기기 미전송 답안은 해당 기기에 계정별로 임시 보존; **같은 계정으로 해당 기기에 재로그인한 뒤** 복구 가능(기기간 로컬 데이터 직접 전송 불가).
- 답안 복구 시 서로 다른 문제의 비충돌 변경은 병합; 같은 문제의 서버/로컬 답안이 다르면 **사용자에게 해당 문제만 선택** 요청. 채점 완료 결과 덮어쓰기 금지. 중복 제출/중복 세트 생성/구세션 경쟁 요청에 대한 멱등성·원자성·버전 검사 수행.
- 로그아웃/계정 전환 시 다른 계정의 복구 데이터가 노출되지 않도록 격리·접근 금지 및 정리 정책 구현.

## 결정 6 — 신고·검토·채점 정정
- 문제별 오류 신고(정답·해설·모호함·오탈자 등). 문제 버전마다 **고유 신고 계정 수 / 해당 버전을 푼 고유 계정 수**로 신고율 계산; 동일 계정 반복 신고는 한 명으로 집계.
- **고유 신고 계정 ≥5 AND 신고율 ≥10%**이면 즉시 자동 출제 중지. 신고가 **1건 이상** 있으면 일일 Cloudflare Cron 기반 AI 재검수 대기열에 등록. 재검수 실패 항목 재시도, 중복 실행 보호, 버전별 결과/근거/시각·감사 기록.
- 재검수에서 실제 오류가 확인되면 신고 수와 무관하게 출제 중지. AI는 근거와 수정안만 생성; **운영 문제 변경은 관리 API의 별도 명시적 작업**으로만 수행. 수정본은 새 버전 자동 검수 통과 후 재공개.
- 진행 중 세트는 문제·보기 스냅샷을 유지하되, **출제 중지된 오류 문항**은 채점 제외, 유효 문항 수를 분모로 정답률 계산. 단 신고 임계치에 따른 잠정 중지와 실제 오류 확정을 구분해 부당한 소급 정정 금지.
- **실제 오류가 확정된 문제**가 이미 완료된 세트에 있으면 최초 제출 답안·최초 채점은 보존하고, 정정 이벤트를 남겨 해당 문항 채점 제외·세트 점수 및 누적/영역별 유효 오답 통계와 추천을 재계산. **앱 알림/이메일 없음**; 과거 결과 상세에서 최초/정정 점수와 사유만 표시.
- 채점 제외 문항은 풀이 이력에는 남기되 유효 오답 가중치/진도·통계에 부당하게 반영하지 않는다. 모든 문항 제외 등 분모 0인 경우 점수를 0%로 오해시키지 않고 채점 불가로 표시한다.

## 결정 7 — 학습 현황 및 확장
- 전체 최초 풀이 고유 문제 수/500, 누적 정답률, 영역별 누적 정답률, 취약 영역 추천만 제공. 시험 준비도 점수/합격 가능성 예측, 기간별 고급 그래프 불필요.
- 취약 영역 추천은 **누적 정답률 + 최소 고유 문제 풀이 수 + 최근 성과**를 결합. 일반 세트·오답 복습·북마크 복습 모두 반영하되 같은 문제 반복의 통계적 영향력을 제한. 데이터 부족 영역은 취약하다고 단정하지 않음. 정확한 계산 파라미터는 하위 설계/BDD에서 근거와 함께 고정.
- 시험을 확장해도 로그인은 공유하지만 진도·오답·북마크·취약 영역·과거 세트/회차 목록은 **시험별로 분리**해 조회.

## 구현 위임 및 수용 게이트
- Mac mini AI 에이전트가 이 계약을 모체로 하위 Issue/ADR/0.2.x 단계, D1 스키마/인덱스, API DTO, 보안 경계, migration/백업/롤백, 테스트 전략을 **의존성 순서대로 구체화**한다. 사용자가 정한 정책을 바꾸려면 별도 합의를 요청한다.
- TDD→BDD와 CI fail-closed, 브라우저 320/375/768/1024/1280 확인, Workers/D1 통합·권한 우회·저장 유실·중복 제출·복구 충돌·세션 경쟁·신고 악용·정정 재계산 테스트를 단계별 수용 조건으로 포함한다.
- ADR-0002/0003/0004/0005/0006/0007/0009/0010/0011의 스택·경계·배포 보안 제약을 유지한다. 본 문서는 세부 구현 설계를 대체하지 않으며, 별도 ADR로 후속 기술 판단을 기록한다.

## 결과 / 제약
- 긍정: 시험별 확장 가능한 문제은행, 데이터 유실 방지, 시험형 풀이와 복습형 채점 분리, 문제 오류의 탐지·정정 감사 가능.
- 비용/제약: 500문제 검수와 자동 재검수 비용, 문제 개정 버전 및 성적 재계산, 클라이언트 오프라인 충돌 복구 복잡도.
