# ADR-0023: 에이전트 컨텍스트 리셋·워커 산출물 검증

## 배경
- 2026-10-18 GLM 5.3 Flash 워커가 #2 OIDC → #3 → #4 세션 → #13 리뷰 → #48 → #49를 **같은 세션**에서 수행했다. 실패 시 컨텍스트는 370K(37%)였고, #49에서 OAuth/session 맥락을 혼동해 domain에 `drizzle-orm` import·stub(`return false`)·무관 모듈 언급을 생성했다.
- OpenCode Go 로그의 실패 시간대(09:56–10:04)에 제공자 429/5xx/context 오류는 없었다. 07:59 HTTP 500·08:29 rate limit은 다른 세션·시점이다. w2 패널 교체 시점에 이전 세션이 종료됐다.
- 원인은 제공자 장애보다 **단위 간 컨텍스트 미분리·산출물 무검증 병합**이다.

## 결정
- **단위마다 컨텍스트를 리셋/컴팩트**한다. 서로 다른 기능·이슈를 같은 세션에 누적하지 않는다. 200K+ 또는 이전 단위 맥락이 남은 세션은 재사용하지 않는다.
- 기존 Herdr 워커 풀만 사용한다. 새 에이전트·페인·리뷰어 생성과 범위 밖 작업은 사용자 승인 후에만 한다.
- 작성자와 다른 모델이 리뷰한다. 큰/횡단 단위는 강한 모델, 작은·결정적 단위는 Flash 계열을 사용한다.
- 수락 전 `check-worker-output.sh`(보고서·변경·domain 외부 import·stub 마커) + `run-gates` + diff/AC/scope 검증을 통과해야 한다. 보고서/테스트 누락, 금지 import, stub, 범위 밖 변경은 거부한다.
- 오염된 산출물은 병합하지 않고 워크트리 변경을 폐기(브랜치 보존)한다. 같은 워커에 재작업을 맡기더라도 컨텍스트를 리셋하고 범위를 좁힌다. 반복 실패 시 다른 모델/워커로 재배정한다.

## 결과
- 긍정: 컨텍스트 오염·불량 산출물의 병합 차단, 모델/제공자 문제와 오케스트레이션 문제의 분리 기록.
- 부정/제약: 단위마다 컨텍스트 준비 비용, 검증 스크립트 실행 단계 추가.

## 대안과 금지 사항
- 장기 세션 재사용, 산출물 무검증 병합, native subagent로의 무단 대체 — 금지.
- 제공자 오류와 모델/컨텍스트 문제를 구분하지 않고 동일 재시도 — 금지.
