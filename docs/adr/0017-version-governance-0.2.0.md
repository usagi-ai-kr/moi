# ADR-0017: 0.2.0 버전·거버넌스·출시 게이트

## 배경
- 0.1.x는 인증·세션·배포 토대다. 다음 학습 제품 목표는 AWS SAA-C03 500문제·20문제 풀이·오답/북마크 복습이다.
- ADR-0008의 '다음 큰 기능은 1.0.0'과 수동 Milestone 연결 방침을 최신 사용자 합의로 대체한다.

## 결정
- 0.1.0~0.1.4는 유지한다. 다음 학습 제품 목표는 **0.2.0(최종 출시)**이며, 하위 구현 단계는 0.2.x로 나눈다. 확정된 제품 요구사항을 임의 축소·변경하지 않는다.
- 모든 Issue는 적절한 Milestone에 연결한다. 생성은 사용자 수동 또는 명시 요청, 연결은 에이전트가 수행한다. 잘못된 Milestone 연결·무단 생성을 금지한다.
- 0.2.0 이후 minor 후보는 추상 `1.0.0` Milestone을 placeholder로 사용하고, 범위가 확정되면 해당 minor Milestone(예: `0.3.0`)을 만들어 옮긴다.
- 각 minor의 최종 patch는 wiki 페이지·annotated tag(`v<minor>.<patch>`)·GitHub Release·`release/<minor>` branch 4종을 모두 남긴다. 하나라도 없으면 릴리스 미완료다.
- **0.2.0 출시 게이트**: 500문제 전량 검수 + 기능/보안/BDD(viewports 320~1280)/Workers·D1 배포 검증 통과. 미통과 시 출시를 금지한다.
- Mac mini AI 에이전트가 의존성 순서로 하위 Issue/ADR/0.2.x 단계를 분할한다. 사용자가 정한 정책 변경은 별도 합의를 요청한다.

## 제품 계약 분할
- 문제은행·품질·관리 API: **ADR-0019**
- 20문제 풀이·오답/북마크 복습: **ADR-0020**
- 저장·복구·단일 세션·신고·정정·통계: **ADR-0021**

## 결과
- 긍정: 버전·마일스톤·출시 게이트의 단일 기준, 0.2.0 범위 임의 축소 방지.
- 부정/제약: 0.2.x 단계 관리와 릴리스 산출물(wiki/tag/release/branch) 부담.

## 대안과 금지 사항
- 0.2.0 범위 축소·출시 게이트 우회·릴리스 산출물 누락 — 금지.
- 새 minor Milestone을 요구사항 확정 전에 양산 — 금지(추상 1.0.0 사용).
