# ADR-0095: 학습 시작 범위 진척도 분자·분모와 재조회 정책

## 배경
- 학습 시작 범위 선택에서 범위마다 실제 학습 진척을 즉시 보여줘야 한다 (#330).
- 기존 `StudyStats.uniqueFirstSolved`는 사용자·시험별 고유 question ID의 최초 채점 풀이를 집계하지만, 전체 분모 500은 고정값이고 영역별 문제 수는 API에 없다.
- 취약 영역 모드는 별도 개인 추천 집합을 만들지 않고 시험 전체 문제 풀에서 선택한다. 약한 영역 전용 분모로 오해할 수 있는 퍼센트를 표시하지 않아야 한다.

## 결정
- 진척도 분자는 기존 `StudyStats.uniqueFirstSolved`와 영역별 `uniqueFirstSolved`를 사용한다. question ID를 기준으로 하며 최초 채점 풀이(correct/wrong)만 센다. 반복 풀이·Pass·미응답·포기는 진척을 추가하지 않고, 정정 제외 시도는 기존 통계 계약에 따라 제외한다.
- 통계 API는 요청 시험의 `questions.status='active'`이고 `current_version_no`가 가리키는 버전이 존재하는 문제 수를 전체·영역별로 읽기 전용 집계해 반환한다. 전체 진척도 분모와 선택 영역 분모는 이 값을 사용한다. 사용자별 분자는 인증 세션으로만 격리하며 분모는 해당 시험의 공개 문제 풀에서 계산한다.
- 분모가 없거나 0이면 숫자 퍼센트를 만들지 않고 진척도 이용 불가 상태를 표시한다. 표시 분자는 분모를 넘지 않도록 제한하고 퍼센트는 0~100% 범위로 표시한다.
- 현재 취약 영역 선택은 시험 전체 활성 문제 풀을 사용하므로 취약 영역별 비율은 만들지 않는다. `시험 전체 진도`라는 라벨로 시험 전체 분자·분모를 명확히 표시한다. 이후 개인별 취약 문제 집합이 추가되면 그 후보 집합에 맞춘 별도 계약을 확정한다.
- 진척도 조회 캐시는 인증 `userId`와 `examId`를 모두 키에 포함하고 서로 다른 키 간 이전 데이터를 placeholder로 보여주지 않는다. 진척도는 학습 범위 화면에서만 조회하며, 제출 성공 뒤 캐시를 무효화하고 화면 포커스 복귀·재연결 시 다시 조회한다. 로딩·조회 실패는 학습 시작을 막지 않으며 실패는 재시도할 수 있다.
- 화면 문구는 `src/ui/copy.ts`에서만 관리하고 시맨틱 `<progress>`와 문구를 함께 표시한다. BDD는 320/375/768/1024/1280px와 200% 확대에서 오버플로·겹침을 확인한다.

## 결과
- 긍정: 기존 사용자별 고유 풀이 집계와 문제 풀의 현재 상태가 같은 화면에 표시되고, 범위별 분모·계정·시험 경계가 명확하다.
- 부정/제약: 진척도 조회에 시험 문제 풀의 읽기 쿼리가 추가된다. 비활성 처리된 문제는 총분모에서 빠지므로 과거 고유 풀이 수가 표시 가능한 문제 수보다 커질 수 있고 이때 표시는 100%로 제한된다.

## 대안과 금지 사항
- 전체 500 고정값 또는 영역 weight의 비례 추정으로 분모를 꾸미는 방식은 채택하지 않는다.
- 취약 영역 모드의 현재 전체 문제 풀에 개인별 취약 분모가 있는 것처럼 표시하지 않는다.
- 학습 진척도를 브라우저의 사용자 제공 값으로 계산하거나 인증 사용자 ID를 요청 파라미터로 받지 않는다.
