# ADR-0042: 리뷰 전담 r 역할과 워커 콜백 기반 오케스트레이션

## 배경
- Herdr workspace `w17`을 o(오케스트레이터)·r(agy, 리뷰 전담)·w1~w3(구현)으로 재편했다(사용자 승인, 2026-10-20).
- 운용 문제: `herdr agent prompt --wait`가 agy의 백그라운드 작업 중 턴 종료를 완료로 오인했고, 파일 폴링 루프와 오케스트레이터의 직접 수정이 발생했다. 리뷰가 o에 집중돼 병목이 됐다.
- ADR-0023(컨텍스트 리셋·산출물 검증)은 유지한다. 이 ADR은 역할 분리와 완료 신호를 보완한다.

## 결정
- 역할: **o**=브리프·디스패치·최종 수락·커밋/PR/병합만. 직접 구현·수정과 게이트 코드 수정 금지(게이트 수정도 워커 단위). **r**=교차 리뷰·재리뷰 전담, 작성자와 다른 모델, 판정·차단 사유를 PR 코멘트와 보고서로 남기고 o에 콜백. **w1~w3**=브리프 단위 구현·테스트·보고서.
- r 산출물이 생기면 w 중 다른 모델이 리뷰한다. 새 패널·리뷰어는 사용자 승인 후에만 만든다.
- 콜백: 완료·blocked·failed 모두 `[callback] unit=<unit> status=<done|blocked|failed> report=<path>` 형식으로 o에 보낸다. `notify.sh`가 `<MOI_WORK_DIR|보고서 디렉터리>/callbacks.log`에 먼저 기록한 뒤 `herdr agent prompt`로 전송하고, 실패 시 `delivered=pending`으로 남긴 뒤 종료 0. o는 pending을 재전송한다.
- 폴링 금지: `--wait`·파일 폴링으로 완료를 추정하지 않는다. 폴백 타이머는 단위 묶음당 1개, 15분이며, 만료 시 패널 출력을 읽어 triage한다.
- 수정 라운드: 차단 사항만 작성자에게 보내며 최대 2회. 비차단 지적은 후속 단위로 기록한다.
- 역할명 o/r/w1~w3은 피처명이 아니므로 "피처명 고정 배치 금지"와 충돌하지 않는다. 단위는 매번 새 브리프로 할당한다.

## 결과
- 긍정: 리뷰 병목 완화, 완료 오인·폴링 제거, 작성자와 다른 모델 리뷰 유지, 콜백 기록으로 누락 추적.
- 부정/제약: 콜백·타이머 운용 비용, r 대기 중 유휴, 로그 파일 관리 필요.

## 대안과 금지 사항
- `--wait` 완료 판정, 파일 폴링, o의 직접 수정·게이트 수정 — 금지.
- 콜백 없는 완료 처리, r 없는 단일 모델 리뷰, 3회 이상 수정 라운드 — 금지.
