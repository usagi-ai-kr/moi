# ADR-0008: 버전 규칙과 Milestone 체계

## 배경
- 일반 SemVer와 다른 프로젝트 내부 버전 관례가 필요하다. Milestone 운영 방식도 초기에 확정해 우선순위 근거를 명확히 한다.

## 결정
- 0.1.x 패치 체계로 진행한다: `0.1.0` 하네스 보강(#9~#12)·scaffold → `0.1.1` Kakao OIDC → `0.1.2` D1 사용자 매핑 → `0.1.3` PASETO 세션·인증 API → `0.1.4` BDD 통합·Workers 배포.
- GitHub Milestone `0.1.0`~`0.1.4`가 각 단계와 대응한다. `0.1.0` Due 2026-10-22(설명에 목표 19:00 KST 명시).
- 다음 큰 기능 단위는 `1.0.0`부터 시작한다(일반 SemVer의 메이저 의미와 다름).
- Milestone 생성·연결은 기본적으로 사용자 수동 작업이다. 에이전트는 사용자가 명시적으로 요청한 경우에만 수행한다(2026-10-18 사용자 요청으로 `0.1.0`~`0.1.4` 생성·연결).
- 우선순위 근거: GitHub Milestone과 이슈 본문의 버전·선행 링크. Milestone이 없으면 이슈 본문 버전이 근거다.
- 단계 완료 시 해당 Milestone을 close한다. 일정 리스크는 테스트·인증 검증 생략이 아니라 scope/일정 조정으로 기록한다.

## 결과
- 긍정: 패치 단위 진척·증거 추적, 하네스 선행을 0.1.0에 묶어 게이트를 우선 확보.
- 부정/제약: 기존 제안(단일 0.x Milestone, 0.2.0~0.5.0 표기)과 달라 이슈 제목·문서 동기화가 필요했다(2026-10-18 반영 완료).

## 대안과 금지 사항
- 단일 0.x Milestone — 패치 재편으로 대체(2026-10-18).
- 1.x Milestone 선생성 — 요구사항 확정 전 금지.
