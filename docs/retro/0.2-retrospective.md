## 3. 사고 및 대응

- dev CI 실패(#320→#322): `review-api.test.ts:432` 기대값이 구 정책(count 1)에 머물러 #315 정책(정답 최신 → 후보 제외)과 충돌. 기대값 수정 + rowid tie-break 결함 수정으로 해결.
- Codex 샌드박스 쓰기 차단: 일부 워커에서 파일 쓰기가 차단되어 재배정/우회 필요. 쓰기 가능 환경 확인 절차 보강 필요.
- 분류기 병합 차단: review 단위에서 차단(B) 발생, 차단 사항만 수정 라운드로 처리(최대 2회) 원칙 유지.
- 워크트리 조기 삭제: 일부 단위 워크트리가 조기 삭제되어 재생성 필요. 삭제 금지 규칙 재확인.
- 콜백 누락: 콜백이 일회성 프롬프트라 놓치는 사례 발생. `tmp/dispatch-queue.tsv` + `dispatch-status.sh`로 점검 수단 추가(ADR-0088).

## 4. 모델별 평가

- GLM: 사용량 한도로 일부 워커가 중단되어 재배정 필요. 작은·결정적 단위에 적합.
- Codex: 컨텍스트 압축으로 장기 단위에서 맥락 손실 위험. 단위를 좁게 쪼개는 것이 안전.
- OpenCode: 제공자 rate limit/세션 이슈 발생. 재시도·세션 리셋 절차 필요.
- MiniMax Flash: 빠른 리뷰/구현에 유용하나 교차 리뷰어로는 작성자와 다른 모델 조합 필요.

## 5. 개선점

- 디스패치 큐와 상태 점검 도구를 기본 절차로 고정한다.
- 콜백 대상은 이름 `o`를 기본으로 사용하고, 워커는 종료 전 반드시 `notify.sh` 호출.
- CI 기대값은 정책 변경 시 함께 갱신하고, flaky/타이밍 의존 테스트는 rowid 등 결정적 tie-break로 보강.
- 워크트리 삭제·reset 등 파괴 명령은 o 승인 없이 금지.
- 모델별 강점에 맞게 큰/횡단 단위는 강한 모델, 작은 단위는 Flash 계열로 배정.
