# 이슈 트리아지 — focus / instant / tuck

출처: 이슈 #6(마일스톤 제안), #7(라벨 의미). `f`/`i`/`t`는 약칭일 뿐이며 **새 라벨을 만들지 않는다**.

## 스크립트 (우선 실행 — repo root에서 실행)
반복·결정적 작업은 스크립트로 수행하고 요약 출력만 읽는다.
- `sh .agents/skills/issue-triage/scripts/new-issue.sh <focus|instant|tuck> "<title>" --milestone <title|number> [body-file]` — 라벨을 검증(약칭 금지)하고 **Milestone 존재를 사전 검증**(미지정·미존재 시 exit 2, 이슈 미생성)한 뒤 이슈를 생성한다. body-file 생략 시 stdin. gh CLI 인증 필요.
- `sh .agents/skills/issue-triage/scripts/new-issue.test.sh` — 검증 회귀 테스트(실패 경로 — 실제 이슈 미생성).

## 라벨 정의

### `focus` (f) — 집중해서 해야 하는 핵심적인 일
- 사용자 목표에 직접 기여하고 충분한 집중 시간·사고·작업 단위가 필요한 핵심 과제.
- 예: Cloudflare 앱 골격 구축, Kakao OIDC 구현, PASETO 인증 구현, 프로덕션 BDD QA.
- 오래 걸린다는 이유가 아니라 **핵심성 + 집중 필요성**으로 분류한다.

### `instant` (i) — 부수적으로 필요하지만 바로 처리하거나 단위가 적은 일
- 본 작업을 뒷받침하는 운영/정리/간단한 설정, 빠르게 처리 가능한 작은 부수 작업.
- 예: Milestone 생성 요청, GitHub 설정 확인, 작은 문서 수정, 값 등록 확인.
- 단순히 긴급하다는 이유로 분류하지 않는다. 핵심 과제가 급하면 여전히 `focus`가 적절하다.

### `tuck` (t) — 나중에 해도 되거나 미리 정리해 둔 일
- 현재 목표를 막지 않고 보류 가능한 아이디어·개선안·추후 검토 과제.
- 예: 로그인 기능 완료 이후의 사용성 아이디어, 비핵심 테마 고도화 제안.
- 잊지 않도록 기록만 하고, 현재 작업을 대체하여 바로 실행하지 않는다.

## 의사결정 순서
1. 현재의 핵심 목표이며 집중이 필요한가? → `focus`
2. 아니라면 지금 바로 처리해야 하거나 작은 부수 작업인가? → `instant`
3. 아니라면 나중에 해도 되거나 미리 적어두는 일인가? → `tuck`

`focus > instant > tuck` 같은 숫자식 우선순위 대용으로 사용하지 않는다. 작업의 성격, 집중도, 처리 시점을 함께 표현한다.

## 검토 결과 라벨 (별도 축, 최대 1개)
작업 성격 라벨과 별개로 **검토 결과**를 표현한다. 하나의 이슈/PR은 (작업 성격 1개) + (검토 결과 최대 1개)를 가진다.
- `reviewed` — 리뷰 수행 완료. **승인·검증 통과를 뜻하지 않는다.** 수정 요청·완료 기준 미충족 상태에 사용.
- `approved` — 기준 충족으로 승인. 이슈에 붙일 때 '설계/작업 수용 승인'인지 '완료 증거 확인'인지 댓글로 명시한다. PR은 리뷰·검증 결과에 근거한다.
- `rejected` — 명시적 반려. 반려 근거를 댓글로 남기며 단순 미완료·수정 필요에는 사용하지 않는다.
- 전이: `reviewed → approved/rejected` 판정 시 이전 검토 라벨을 제거한다. 라벨 변경 사유와 근거(이슈/PR·테스트 증거)를 댓글로 기록한다.
- `closed`/`merged`와 검토 라벨은 별개이며 상태 전환을 자동으로 일으키지 않는다.

## 승인·우선순위 (이슈 #288)
- `focus` 라벨 또는 `0.2.4` Milestone 이슈를 후속으로 옮기거나 범위에서 제외할 때는 **사용자 명시 승인 근거**를 댓글/PR에 남긴다. 에이전트 코멘트만으로 승인을 대체하지 않는다.
- 이슈 라벨·Milestone과 사용자 최신 지시를 먼저 대조한 뒤 분류한다.

## 운영 규칙
- 각 이슈는 작업 성격 라벨(focus/instant/tuck 중 **한 개**)과 검토 결과 라벨(최대 1개)로 구성한다.
- 라벨은 작업 성격 분류이며 진행 상태(open/blocked/in-progress/closed)를 나타내지 않는다. 진행 상태는 이슈 상태·본문/PR로 관리한다.
- 분류가 바뀌면 라벨을 변경하고 사유를 댓글/PR에 남긴다.
- `0.1.0`–`0.1.4` 실제 구현은 `focus`, GitHub Milestone 작성·수정 제안은 `instant`, 추후 개선 아이디어는 `tuck`.
- 기존 GitHub 라벨 `focus`, `instant`, `tuck`을 그대로 재사용한다. **라벨 생성·이름 변경·삭제 금지.**

## 용어 규칙
- 저장소 템플릿·브랜치 보호·README·운영 절차 정비를 통칭할 때는 **저장소 운영 체계 정비**를 사용한다. `저장소 위생`이라는 직역 표현은 새 Issue·PR·문서에서 사용하지 않는다.
- 권한·승인·보호 정책만 다루면 **저장소 거버넌스**, 개발 절차에 집중하면 **개발 워크플로 표준화**로 구분한다.

## Milestone 정책 (이슈 #6, 2026-10-18 재편)
- Milestone **생성**은 기본적으로 사용자의 수동 작업이다(에이전트는 명시 요청 시 대행).
- **모든 이슈는 적절한 Milestone에 연결(부착)한다 — 예외 없음.** 연결은 에이전트가 수행하며, 알맞은 Milestone이 없으면 생성하지 말고 사용자에게 요청한다. 잘못된 Milestone 연결 금지.
- 연결 예: 단계 구현 이슈 → 해당 패치 Milestone, 하네스·저장소 운영 체계 정비 → `0.1.0`, Kakao 설정 → `0.1.1`, Cloudflare·배포 준비 → `0.1.4`, 학습 실사용 → MS9(`0.2.2` 저장·복구)·MS10(`0.2.3` 작성·#134)·MS11(`0.2.4` 실사용/디자인·#132·#70·#131), 0.3 이관 → MS12 `0.3.0`으로 고정(PR #130/#133 draft 포함).
- 현재 체계: 패치 마일스톤 `0.1.0`~`0.1.4` — `0.1.0`=하네스 보강(#9~#12)+scaffold(#1), `0.1.1`=#2, `0.1.2`=#3, `0.1.3`=#4, `0.1.4`=#5. `0.1.0` Due `2026-10-22`(KST, 설명에 목표 19:00 명시). 그 다음 학습 실사용: `0.2.2`(MS9) 저장/복구·`0.2.3`(MS10·#134) 워크스페이스 작성·`0.2.4`(MS11·#132·#70·#131) 학습/디자인/favicon. `0.3.0`(MS12)=#51·#53·#54·#55·#121/#128/#129·#65/#71/#72, 추상 `1.0.0 — 이후 minor 버전 통합`.
- 추상 `1.0.0`은 실제 major 릴리스 계약이 아니라 0.2.0 이후 minor 요구사항 확정 전까지의 placeholder다. 실제 minor 범위가 확정되면 해당 minor Milestone(예: `0.3.0`)을 만들어 옮긴다. 구체 minor Milestone은 요구사항 확정 시 생성한다(추상 `1.0.0`은 예외로 허용).
- 완료 정의: 단계별 이슈 closed + 해당 단계 TDD/BDD/게이트 통과. 최종 단계는 실제 Kakao 계정 smoke 성공 + 배포 URL·커밋 SHA 확인 + PASETO 만료/변조/폐기 검증 포함.
- minor 최종 patch는 wiki/tag/release/`release/<minor>` branch 4종을 남긴다(하나라도 없으면 릴리스 미완료). 상세는 `release-deploy-workers` 스킬.
- 우선순위 근거: Milestone과 이슈 본문의 버전·선행 링크.

## 이슈/PR 관례
- 새 구현 이슈는 선행 이슈를 명시하고 제목에 버전(`0.x.0`)을 포함한다.
- PR에는 테스트 위치/명령/결과, 배포 URL, commit SHA, 남은 blocker를 기록한다.
- 브랜치/PR 플로우: `main ← dev ← 기능 브랜치(feat/fix/chore/docs/test)` — 모든 병합은 PR로만 한다. 직접 push·force push 금지. 상세는 `AGENTS.md`의 브랜치·PR 플로우 참조.
